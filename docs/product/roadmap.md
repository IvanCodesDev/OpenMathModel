# 产品路线图

> 状态基线：2026-08-11。括号内周期是阶段投入量估算，不表示已经完成或固定发布日期。

## 阶段状态

| 阶段 | 当前状态 | 已有基础 | 当前出口缺口 |
|---|---|---|---|
| Phase 0 工程底座 | **收尾验证** | Web/API/Agent/Contracts 可运行；首页发送→真实 Project/TaskRun→workspace、审批、SSE、Artifact 主链已接通（`/confirm` 为直接访问的草稿复核入口） | 真实登录浏览器创建断言、重复提交幂等断言与关键路由自动视觉回归 |

## 跨阶段实施约束

- 当前 14 个 Web 页面是产品界面基线，路线图中的“实现”“接入”和“完善”均指在现有页面的既有区域中填充真实数据与状态，不代表重新设计页面。
- Web 对接遵循“后端契约 → 类型化 API 客户端 → 页面控制器/视图模型 → 现有 DOM”的顺序；不得用新的整页组件替换当前页面。
- 数据准备、模型方案、实验结果、论文写作和成果交付进入真实对接前，先补齐对应页面级契约，再实现后端，再绑定前端。
- 每个阶段除类型检查、测试和构建外，还必须按视觉基线走查关键页面。详细规则见 [`Web 页面基线与前后端对接规范`](../development/web-ui-baseline-and-api-integration.md) 和 [ADR-0006](../adr/0006-preserve-web-ui-and-integrate-api.md)。

## Phase 0：工程底座（1–2 周，收尾验证）

- 建立 Web、API、Worker、Agent、Contracts 的最小可运行闭环。
- 保留当前已经落地的设计 Token、Shell、侧栏、Agent 面板和工作区布局，在原有交互位接入控制面数据。
- 定义 `Project`、`TaskRun`、`AgentEvent`、`Artifact` 四个首批协议。
- 建立格式化、类型检查、单测、构建与契约检查。

**退出标准**：浏览器在现有“新建任务 → 实时执行”页面链中创建任务（确认页作为直接访问入口走同一流程），后端产生 Agent 事件，页面实时更新并可恢复刷新前状态；首页、确认页和执行页与视觉基线一致。

## Phase 1：数学建模 MVP（4–6 周，待进入）

- 题目输入、附件上传、目标与约束提取。
- 为 `DatasetProfile`、`PlanProposal`、`ExperimentSummary`、`DocumentDraft` 和 `DeliveryManifest` 补齐契约与 API。
- 在现有数据准备页接入 CSV/XLSX 数据画像、缺失值和异常值建议。
- 在现有模型方案页接入“主候选方案、可用基线、条件回退方案”等角色化方案、用户确认和 Python 实验执行。
- 在现有实验结果页接入指标与图表、失败重试、日志与产物下载。
- 在现有论文写作与完成页接入大纲、章节草稿和成果导出。

**退出标准**：使用一个公开样例题，从题目和数据完整走到可下载报告；运行可复现。

## Phase 2：桌面端与本地执行（3–4 周，原型储备）

- Tauri 壳、工作区选择、系统密钥库和本地文件授权。
- 本地 Python 环境检查、受控进程执行、资源限制。
- 云端项目与本地产物同步策略。
- Windows/macOS 安装包、更新和崩溃收集。

**退出标准**：桌面端复用同一套 UI，可对本地数据完成 MVP 流程。

## Phase 3：专业能力（持续储备）

- 建模方法库、赛题库、论文库和可引用证据。
- 多 Agent 专家角色与动态评审，但仍由单一状态机统一推进。
- 参数搜索、消融实验、敏感性分析、稳健性分析。
- 团队协作、版本对比、批注和模板市场。
- Agent 与模型质量评测、成本和延迟优化。

## MVP 优先级

### Must

- 项目/任务、数据导入、计划确认、实验执行、实时状态、结果与报告导出。
- 可暂停/恢复/重试、Artifact 校验和、错误追踪、最小权限执行。

### Should

- 多模型供应商、桌面本地执行、论文编辑器、方法模板。

### Later

- 多人实时协作、复杂插件市场、移动端、过早的微服务拆分。
