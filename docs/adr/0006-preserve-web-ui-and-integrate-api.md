# ADR-0006：保留现有 Web 页面并通过适配层对接 API

- 状态：Accepted
- 日期：2026-08-09
- 取代：ADR-0004 的 React Router、TanStack Query 与替代页面方案

## 背景

当前 `apps/web` 已有 14 个完整产品页面，包含首页对话输入、任务确认、任务执行、项目列表，以及数据准备、建模方案、实验结果、论文编辑和知识资源页面。用户确认这些页面的视觉、布局和交互语言就是产品方向。

后端已经提供项目、任务运行、步骤、审批、事件流、产物和账户接口。此前为了接入这些接口，曾新增另一套路由、页面壳和任务执行页。该实现虽然通过类型检查和构建，却改变了已确认的对话与建模流程界面，现已回滚。

问题不是“要不要对接后端”，而是“用什么边界对接”：后端能力需要进入现有页面，不能反过来要求页面迁就新的前端架构。

## 决策

### 1. 现有页面是产品 UI 合约

以下入口保持现状：

- `apps/web/src/App.tsx`：现有路径到 14 个页面的映射；
- `apps/web/src/screens.tsx`：页面到 `OpenMathModelScreen` 的映射；
- `apps/web/src/components/OpenMathModelScreen.tsx`：现有 markup 渲染与 `activateScreen` 生命周期；
- `apps/web/src/legacy/openmathmodel-ui.ts`：页面结构、稳定选择器和交互；
- `apps/web/src/styles.css`：当前视觉系统与响应式布局。

“legacy”只是迁移来源的技术命名，不代表页面可以被自动替换。除非有明确的 UI 设计任务，上述页面结构就是正式产品基线。

### 2. 前后端通过适配层连接，不创建替代页面

前端对接分为三层：

1. 类型化 API 客户端：处理 `/api`、Cookie、错误信封、幂等键和 SSE；
2. 页面控制器：把契约对象转换为现有页面需要的 view model；
3. DOM 适配器：只更新既有选择器对应的文本、列表、状态、按钮可用性和图表数据。

允许新增 `apps/web/src/api/` 与 `apps/web/src/integration/`。控制器可以在页面激活后挂载，也必须返回清理函数并避免重复监听。它们不得返回新的整页 JSX，不得重建侧栏、对话区、建模工作区或页面路由。

### 3. 保留当前路由机制

当前 14 条扁平路径继续由 `Map<path, Component>` 与全页跳转承载。接入 API 不以引入路由库为前提。未来确有深层路由需求时，必须单独提出 UI 迁移任务，并证明所有基线页面视觉和行为保持一致。

### 4. 当前优先使用平台能力

- REST：原生 `fetch`；
- SSE：原生 `EventSource`；
- 状态：页面控制器内的显式状态与服务端事件；
- 跨页最小上下文：URL 查询参数、`sessionStorage` 和服务端 `project_id/run_id`。

引入状态管理或数据请求库需要独立 ADR，不能作为普通 API 对接的附带改动。

### 5. 契约先于页面数据替换

已有项目、任务、步骤、审批、事件和产物契约可先接入首页、确认页、任务执行页、项目页和完成页。数据准备、模型方案、实验结果和论文编辑需要的结构化字段尚不完整，必须先补充契约与 API，再把真实数据映射进现有卡片和表格。

不得把后端日志字符串硬拆成页面数据，也不得为了绕过契约缺口创建另一套页面。

### 6. 登录保持在现有产品外壳中

受保护接口使用同源 Cookie。遇到 401 时，在现有外壳内打开登录/注册模态层或抽屉，并在成功后重试原动作。独立 `/login` 整页需要单独的 UI 设计确认，不能由 API 对接任务自动新增。

### 7. 视觉回归是强制门禁

涉及 Web 页面的交付必须同时通过：

- 类型检查、ESLint、生产构建；
- 14 条路由可达；
- 首页、任务执行、数据准备、建模方案、实验结果、论文编辑的固定视口截图对比；
- 关键交互清单：发送、返回、进入下一阶段、方案选择、审批、暂停/恢复、附件和产物下载。

只通过构建或 API 测试，不能宣称页面完成。

### 8. 明确授权的建模阶段工作台更新

2026-08-09 的明确 UI 设计任务将数据准备、模型方案和实验结果三个页面统一为同一套简约双栏工作台。该更新直接修改现有页面 markup 与覆盖样式，不建立第二套路由或页面实现；左侧 Agent、顶部任务栏和右侧标签工作区必须抽取为可复用结构。

后续视觉复核进一步确定：三页沿用产品原有紧凑顶栏，左侧仅保留返回按钮与项目名称，右侧保留工具按钮，不重复显示产品字标、竞赛元信息或运行状态；顶部容器和阶段页签保持透明并移除底部分隔线；Agent 面板默认采用 27% 左右的可拖动比例，增加工作台四周及面板内部留白，通过持久化分隔线响应不同桌面视口。Agent 标题下移并靠近执行区，步骤字号、行距与完成图标进一步压缩；折叠只作用于当前 Agent 面板，主操作按钮在悬停和聚焦状态保持黑底白字。Agent 底部继续使用原有大输入盒，不因参考图复刻改成另一套输入组件。

第四轮视觉复核移除建模顶栏的全屏按钮，并将顶栏内容整体向下做光学居中。建模对话框中的自动模型标签统一为 `Auto`，使用更紧凑的浅灰按钮并靠近右侧发送按钮；完成步骤改用绿色方形完成图标。右侧工作区页签借鉴文档标签的圆角浅灰选中态，但保留本产品图标、字号与透明容器，不照搬参考产品。

第五轮视觉复核将完成状态调整为独立的绿色圆形对钩图标。右侧工作区改为“外置标签条 + 独立正文卡片”，标签条不再包含在正文边框内，正文卡片相应缩小。选模按钮取消实色背景，并使用受容器宽度约束的三列布局、文本省略和窄宽容器规则，避免长模型名挤压或覆盖左侧工具与右侧发送按钮。

第六轮继续收紧共用工作台布局：模型选择器按内容宽度收缩并靠右停靠，短名称不再占据固定列宽，长名称仍以最大宽度和省略号保护工具区；正文卡片上扩至与左侧对话卡片同高，标签带覆盖在正文卡片顶部且不再占用独立纵向空间；数据、方案和实验内容统一增加轻量纵向留白，分隔条保留命中区域和拖动行为但隐藏视觉线条。

第七轮依据视觉复核将标签带从正文卡片覆盖层调整为正文卡片上方的独立兄弟层。正文卡片不再为标签带保留内部顶部空间；标签带自身保持透明，未选标签取消背景、边框与阴影，仅选中标签显示浅灰胶囊状态，从而消除正文白底和边框在标签后方形成的盒状泄露。

第八轮进一步按实际页面复核将工作区标签带提升到项目顶栏，与返回按钮、项目名和操作按钮同一行；标签节点在渲染建模外壳时从正文工作区中抽离并复用原有交互属性，正文工作区不再消耗标签高度，右侧正文卡片重新与左侧对话卡片等高。

第九轮参照文件式项目工作台的横向秩序，将顶栏调整为返回与项目名、历史与文件工具、工作区标签、右侧设置依次排列，标签从居中改为紧随工具区向左排列；同时移除左侧 Agent 区域的白色外壳、边框和圆角，仅保留内容与输入框，使对话区域直接融入页面背景。

第十轮纠正顶栏工具位置：任务历史和任务文件恢复到右侧操作区，本建模工作台不再显示设置按钮；工作区标签的左起点绑定 Agent 分栏宽度变量，与右侧正文列左边缘对齐，并在拖动分栏或窗口变化时同步更新。

第十一轮仅将顶栏工作区标签整体下移 4px，使标签文字与右侧任务历史、任务文件图标的视觉中心线更一致，不改变正文对齐、分栏联动和其他顶栏元素位置。

第十二轮继续将工作区标签下移量从 4px 增加到 8px，其他顶栏工具、正文卡片和分栏联动位置保持不变。

第十三轮继续将工作区标签总下移量从 8px 增加到 12px，仅调整标签带的垂直位置，其他顶栏工具、正文卡片和分栏联动位置保持不变。

第十五轮按反馈撤销第十四轮正文密度改造，并将数据、方案、实验页面的切换导航从项目顶栏移回右侧正文白色盒子的内部顶部。标签恢复为共享底线的轻量导航，不使用彼此独立的胶囊背景；正文、空状态与实验报告统一从导航下方开始，左侧对话区和流程顺序保持不变。

第十六轮移除建模流程页右上角重复的任务历史与任务文件图标，仅保留左上角返回按钮和项目名称。顶栏改为只承载左侧项目上下文的透明覆盖层，右侧正文卡片利用释放出的右上区域向页面顶部扩展；左侧对话区仍从项目栏下方开始，分栏拖动与三页标签交互保持不变。

第十七轮扩大三个建模主页面各内容区之间的纵向间距，使报告、指标、表格和说明更均匀地使用正文高度。同时补齐数据阶段的原始数据、清洗数据、字段说明，方案阶段的模型假设、符号表、实现计划，以及实验阶段的结果图表、结果表、运行日志、模型代码。所有次级页面复用同一套文档标题、指标、表格、状态、代码与结论组件，不新增路由或改变阶段顺序。

第十八轮按反馈将实验阶段的结果图表、结果表、运行日志、模型代码四个次级页面改用成果检验主页面的报告卡片模板。四页均采用“标题—检验结论—三项指标—核心内容—双栏解释—运行元数据”的结构，具体内容分别对应图表解读、指标阈值、执行轨迹和代码复现；页签、路由、左侧 Agent 区与流程顺序不变。

第十九轮根据最终成果页面截图与 `completeScreen` 源码纠正第十八轮的模板理解。结果图表、结果表、运行日志、模型代码不再使用实验报告卡片，而是直接复用最终成果页的 `stage-document complete-wrap`、完成状态、项目标题、`result-summary`、交付文件表和底部操作区；四页分别替换为图表、指标、日志和代码的摘要与下载文件，现有页签和路由保持不变。

本次授权仅覆盖：

- `/workspace/data`；
- `/workspace/model-plan`；
- `/workspace/experiments`；
- `/workspace/paper-editor`；
- `/task/complete`。

第二十轮根据明确反馈，把论文编辑页与完成页加入聚焦工作台视觉基线。两页必须与实验结果的四个结果文档共享分栏、正文盒子、轻量标签、摘要行、文件表和底部操作区；论文正文的 `contenteditable`、格式命令与检查/导出/交付动作，以及完成页的文件预览、继续优化、复制任务和下载动作必须原位保留。首页、确认页和任务运行页保持原样。后端接入仍必须把结构化数据填入这些页面现有槽位。

第二十一轮缩减论文编辑页正文槽位：`/workspace/paper-editor` 的右侧盒子只呈现论文大纲、编辑工具栏和 `contenteditable` 论文正文，不再承载阶段摘要、同步状态、工作区标签、辅助检查模板或交付文件模板。检查、导出与完成交付动作并入编辑工具栏，以保留功能但避免形成第二层成果文档。该变更不影响左侧 Agent、分栏拖动、路由与 `/task/complete` 的最终成果模板。

## 结果

前后端仍然完整对接，但对接方向固定为“真实数据进入现有页面”。这样可以保留已确认的产品体验，同时逐步消除演示数据。代价是需要为页面建立稳定 view model 和 DOM 适配器，并在契约不足时先完成后端设计。
