# ADR-0011：编排选型——显式状态机加分层有界循环，不引入通用图编排

- 状态：Accepted
- 日期：2026-08-20
- 关联：ADR-0007、ADR-0009、ADR-0010、[系统架构](../architecture/system-overview.md)、[工作台对接规范](../development/frontend-backend-agent-integration.md)

## 背景

Agent 生态的主流编排框架（LangGraph 一类）以「图」为核心抽象：节点自由连边、运行时可改拓扑、循环用图上的环表达。围绕本项目由此反复出现两个问题：

1. 要不要做 loop engineering——为自我修正循环建立统一框架？
2. 要不要做 graph engineering——把七阶段状态机替换或包装为通用图编排？

本 ADR 固化当前事实与结论，避免同类讨论重复发生。

当前编排事实（2026-08-20）：

- `agents/core` 是显式状态机：合法转换矩阵、禁止跳段、审批门（`NEEDS_REVIEW`）、终态冻结，均有独立测试覆盖；
- 事件溯源：事件先持久化后应用（emit→apply），每个引擎场景断言 `replay(events) == live snapshot`；
- `agents/evals` 金标端到端用例精确断言完整 25 事件轨迹；
- ADR-0007 规定一份 `ModelingWorkspaceView` 同时驱动 Agent 左栏与右侧页面，节点→页面是固定映射表；
- 有界循环已经存在于四个层次（见决策 2），`thinking`/`llm_call` 过程事件已进入 `run.log` → SSE → 页面活动流。

## 决策

### 1. 编排机制维持「显式状态机 + 节点注册表」

运行拓扑唯一由 `agents/core` 状态机定义。P4 以节点注册表替换 `SIM_NODES`；不引入通用图编排引擎——既不采用 LangGraph 等图框架，也不自研 DAG 引擎。

依据是三条承重不变量，通用图编排与它们逐条冲突：

| 不变量 | 事实来源 | 与图编排的冲突 |
|---|---|---|
| 金标轨迹回归 | `agents/evals` 精确断言 25 事件序列 | 动态拓扑使事件序列不可穷举，确定性回归失效 |
| 单投影驱动双栏 | ADR-0007 禁止左右两侧分别推导阶段 | 图拓扑要求重写投影语义与六页固定映射 |
| 回放等于快照 | 每个引擎场景断言 `replay(events)==snapshot` | 并发分支要求 reducer 处理偏序合并，复杂度陡增 |

### 2. 循环采用「分层有界」纪律，不建通用 loop 框架

循环不是一个框架，而是四层各自的有界机制。以下为已实现的现状，是后续实现的对齐基准：

| 层 | 机制 | 边界 |
|---|---|---|
| 传输 | `omm_api/llm.py` 备用接口切换 | 仅超时/网络层失败/429 触发；模型侧 4xx/5xx 不重试；流式开始后不回退 |
| 节点 | 结构化输出校验失败修复 | JSON Schema 校验 + 一次修复重试 |
| 步骤 | Worker attempt 语义 | 崩溃固化为显式 failed attempt 后 attempt+1 重跑；重复投递幂等 |
| 运行 | 审批门与检查点 | `NEEDS_REVIEW` 停机待人工，approve 后从检查点续跑 |

### 3. P4 实验节点内环规范（新增约束）

真实实验节点（`EXPERIMENTING`）的「生成代码 → 运行 → 报错 → 修复 → 再运行」内环落地时必须满足：

1. **有界**：显式预算上限，轮数、token、墙钟时间三者至少取其二；耗尽即如实失败，不静默续跑；
2. **事件化**：每轮修复 emit `thinking`/`llm_call` 过程事件（复用既有通道），页面活动流可见；
3. **对外原子**：整个内环对状态机仍是一次 `step_run` attempt；内环不产生新的领域阶段；
4. **产物可追溯**：每轮生成的代码与运行输出经现有 Artifact 端口写入，不落野文件。

### 4. 并行需求的承接方式

将来多方案并行实验的需求，用**同阶段内 step_run 扇出**承接：Worker 的幂等重投与租约语义已按此验证。不为并行修改状态机拓扑，不引入图。

## 结果

正向：

- 编排选型有了可引用的明确立场，评审不再重复论证；
- P4 实验节点内环有了实现规范，全部复用既有基建（过程事件通道、Artifact 端口、attempt 语义），增量成本低；
- 三条承重不变量作为显式约束被保护。

代价与约束：

- 新增领域阶段仍需走契约 → 投影 → 页面映射的全链路修改，图框架「自由加节点」的便利被有意放弃；
- 未来若出现真正的动态拓扑需求，必须先修订本 ADR，不允许绕过状态机私接编排。

## 重新评估条件

以下任一以产品需求形式成立时，重开本决策：

1. 多 Agent 协作或对抗（方案辩论、交叉评审）成为产品功能，且无法折叠进单一阶段节点；
2. 需要用户可见、运行时动态生成的子任务分解树；
3. 并行实验扇出超出「同阶段 step_run」语义（如跨阶段流水线并行）。

届时优先评估「受限扩展状态机」（并行组、子状态机），通用图引擎仍是最后选项。
