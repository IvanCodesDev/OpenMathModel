# ADR-0025：论文导出改为「统一文档模型 → 四种格式」，PDF 由服务端无头浏览器打印

- 状态：Accepted
- 日期：2026-10-03
- 关联：ADR-0012（论文 LaTeX/PDF 导出契约；本 ADR 在其阶段 A 上增加 HTML 源，契约 additive）、ADR-0006（界面基线：只换导出菜单的选项与行为，不动页面结构）、ADR-0008（界面本地化：新文案进英文词典）

> **修订（2026-10-07）**：Word 导出不再插断点。用户电脑上的 `.docx` 多由 WPS 打开，WPS 把零宽空格排成有宽度、两端对齐时还会被拉伸的空格，长标识符显示成 `da ta_ so u r ce`；正文样式的「允许西文在单词中间换行」（`w:wordWrap=0`）又让单词、数字在行尾任意字母处被劈开（`S|OC`、`240|6`）。两者都已去掉，正文里原有的零宽空格也一并去掉，长串按 Word / WPS 默认规则整串挪行；表格列宽改为三档分配。同日再修订：长串整串挪行后，两端对齐把上一行剩下的字摊开（「基　线　为」「降　　至」），含约 11 个西文字符以上不可断片段的段落、列表项、引用改为左对齐，其余段落照旧两端对齐。同日第三次修订：左对齐后长串仍整串挪行，行尾空出一大截、一行只放一个「键=值」；长串改为在分隔符后插 1 pt 的普通空格作断点（WPS 不在零宽空格处断行，普通空格在 Word / WPS 里都是断点），紧跟数字的负号换成不断行连字符 U+2011，含长串的段落仍左对齐。见第 6 节「Word」一条。HTML / LaTeX 不变。

## 背景

2026-10-02 用户反馈论文完成后的下载：排版、渲染都有问题，图片不在；Word 非常糟；PDF 换行后出现大面积空白、字母与标点间距很大，而且一点就弹打印界面；LaTeX 同样要优化。

用真实论文（7 节、5 张图、约 2.1 万字）复现，定位到五个根因：

1. **块级公式写在段落中间时正文丢字**。模型常写 `学习目标为\n$$…$$\n其中…`（前后不空行），`renderMarkdown` 把 `$$…$$` 当行内占位，产出 `<p>…<div 公式>…</p>`；浏览器解析时 `<div>` 截断 `<p>`，公式后的「其中……」成了游离文本。编辑器只收元素节点，这段话整段丢失，公式前后各多一个空段落——「大面积空白」由此而来，编辑器和所有导出都受影响。
2. **长英文串 + 两端对齐**。`metrics.test_acc_iris_mlp_adam=0.99166667` 这类无空格长串中间无处可断，只能整串挪到下一行，上一行被两端对齐硬拉开——「字母和标点间距很大」。
3. **Word 是 HTML 冒充 `.doc`**（MHTML）：Word 不加载外链样式、看不懂 KaTeX 的 HTML 排版标记，公式散成乱码，标题、表格没有样式。
4. **PDF 走 `window.print()`**：必然弹打印框；表格容器 `overflow-x:auto`、代码块不换行，打印时被裁。
5. **LaTeX 序列化缺项**：列表、引用、h4 没处理；表格全用 `c` 列，长文本冲出页面；图件路径带引号；KaTeX 认而 LaTeX 没有的宏直接编译失败。

四种导出各拼各的，同一个问题要修四遍，是第 3~5 条长期存在的结构性原因。

## 决策

### 1. 块级公式成块（编辑器与全部导出共用）

`renderMarkdown` 把 `$$…$$` / `\[…\]` 当块级占位，段落在公式处切开；公式后的续段标 `md-continue`（不缩进；LaTeX 里紧接公式环境、加 `\noindent`）。表格行、列表、引用里的公式不拆。

### 2. 统一文档模型

导出时先把编辑器 DOM 读成 `PaperDocument`：块级为标题 / 摘要 / 关键词 / 章节标题 / 段落 / 公式 / 列表 / 引用 / 表格 / 图 / 代码，行内为文本 / 强调 / 行内公式 / 行内代码 / 换行。Word、LaTeX、HTML、PDF 四种格式都从这一个模型序列化：

| 文件 | 职责 |
|---|---|
| `apps/web/src/integration/paper-document.ts` | 模型与 DOM 读取（兼容终稿、手改草稿与旧版游离文本）、长串断点、共用表格布局 |
| `paper-docx.ts` / `paper-latex.ts` / `paper-html.ts` | 三个序列化器（PDF 用 HTML 序列化结果打印） |
| `paper-export.ts` | 编排：抓图 → 读模型 → 生成 → 下载；PDF 请求服务端并轮询，失败退回浏览器打印 |
| `apps/web/src/text/mathml-omml.ts` | KaTeX MathML → Word 原生公式（OMML） |

编辑器里的插图是需要登录 Cookie 的同源下载链接，原样写进文件就是死链；导出前逐张抓成字节内嵌，抓不到的保留原链接、不阻断导出。

### 3. Word：浏览器内生成真正的 `.docx`

手写 OOXML、fflate 打包：A4、页边距 2.5 cm，正文宋体 / Times New Roman 小四、1.5 倍行距、首行缩进 2 字符、两端对齐；标题黑体并带大纲级别（导航窗格可用）；三线表；图片按版心等比缩放内嵌（SVG / WebP 先转 PNG）；页脚居中页码。公式走 KaTeX → MathML → 自写转换器 → OMML，在 Word 里可以继续编辑。

### 4. PDF：服务端无头浏览器打印，前端直接下载

- **契约（additive）**：`CreatePaperExportInput` 增加 `source_html`，与 `source_tex` 必须且只能给一个（否则 422）；`source_html` 只用于 `format=pdf`，字节上限单独配置（`OMM_PAPER_EXPORT_HTML_MAX_BYTES`，默认 32 MB——图片与 KaTeX 字体都以 data URL 内联）。状态机、产物、血缘、并发与队列限制沿用 ADR-0012。
- **引擎**：Chrome / Edge / Chromium 任一（`OMM_CHROMIUM_PATH`；空则探测 PATH 与各平台默认安装位置）。纸张与页码听 HTML 里的 `@page`（A4、页脚居中页码）；字体全部装载、图片全部解码后才打印（KaTeX 字体是 `font-display:block`，没装好时字形是隐形的）。
- **隔离**：HTML 经 DevTools `Page.setDocumentContent` 写进 `about:blank`（读不到 `file://`）；文档最前强插 CSP，禁脚本、禁一切外部资源，图片 / 字体只认 `data:`；浏览器进程挂一个不存在的代理，漏网请求全部落空；独立临时用户目录、超时强杀。
- **前端**：拿到产物直接下载，不弹打印框。只有服务端找不到浏览器（任务落 `UNSUPPORTED`）、论文没关联项目、请求失败或超时时，才退回浏览器打印，并在提示里说明原因；同一用户已有导出在排队（409）时明说原因，不悄悄退回。

不用 Tectonic 出这份 PDF 的原因：编辑器公式由 KaTeX 渲染，KaTeX 认而 LaTeX 不认的写法、模型写出的非标准宏会让编译直接失败，用户点「导出 PDF」拿到的是失败；浏览器打印与编辑器所见一致，不存在宏失败。Tectonic 首次编译还要联网拉宏包，而 Edge 是 Windows 自带。`source_tex` 路线保留不变，供需要真 LaTeX 排版的场景使用。

### 5. LaTeX：重写序列化，导出 zip

- `main.tex` 与 `figures/`（ASCII 安全文件名，如 `fig1-convergence_curve.png`）打成 zip，xelatex 编译或整包上传 Overleaf（选 XeLaTeX）。
- `ctex` + `geometry`（A4、2.5 cm）+ `booktabs` 三线表 + `fvextra`（代码块可折行）；列表、引用、h4、行内代码、续段都有对应写法；西文用 TeX Gyre Termes，找不到就用默认字体。
- 表格按内容定列宽：短列取自然宽度，剩余版心按比例分给长列，用 `p{}` 折行列（居中 / 左对齐）；排不下依次降到 `\footnotesize`、`\scriptsize` 并收紧列距；行数多到一页放不下的用 `longtable` 跨页、表头每页重复。
- 补 KaTeX 认、标准 LaTeX 没有的常用宏（`\R`、`\argmin` 等，用 `\providecommand`，不覆盖论文自己的定义）；控制字符清掉。

### 6. 断行与标点禁则（HTML / Word / LaTeX 一致）

- 16 个字符以上的拉丁串：`_ = / : , ; \` 后、字母前的 `.` 后可断；字母串内部也可断，两侧各至少留 2 个字母；切完仍有 16 字以上没有断点的片段（长小数、哈希）每 12 字补一个断点；数字之间不断。只在分隔符后断时，一行几乎全是长串的行尾放不下下一段，本行仅有的空格就被拉开，所以字母之间也要给断点（代价是行尾的标识符可能从字母中间断开，不加连字符）。
- HTML 里断点是零宽空格，Word 里是 1 pt 的普通空格、规则另定（见下面「Word」一条）。LaTeX 把长串包进 `\ommid{…}`，由导言区的宏逐个记号判断：分隔符后罚分 0，字母之间罚分同连字符断词（`\hyphenpenalty`），断开后一侧不足 2 个字母时更高（`\@medpenalty`），TeX 的整段优化因此优先断在分隔符处；断点不逐个写进源码，`.tex` 仍然可读。
- HTML / PDF 的两端对齐按字符分摊（`text-justify: inter-character`）：浏览器逐行排版、不回头调整前面的行，行尾放不下的是长数字这类断不开的串时，剩余空白摊到整行字符之间，不堆在几个空格、标点旁边。
- 长行内公式在顶层逗号后插 `\allowbreak`（KaTeX 与 LaTeX 都认；Word 不加）。
- 浏览器在行内公式边界总允许断行、不看标点禁则，「(x_i,y_i)，其中」会把「，」甩到下一行行首：源码 ≤24 字的短公式连同紧贴的标点整组不断行。
- Word：范数竖线换成 Cambria Math 里直立的字形；相邻同字体的单字变量合并成一个 run，避免字距被拉开。
- Word（2026-10-07 修订）：不插零宽空格（WPS 不在 U+200B 处断行，还按正文字号给它排宽度），也不开「允许西文在单词中间换行」（单词、数字在行尾任意字母处被劈开）；U+200C（Word 的「无宽度可选分隔符」）在 WPS 里不占宽、但也不在那里断行，同样不用。11 个字符以上的拉丁串在 `_ = / ; \`、后面不是数字的 `, :`、字母前的 `.` 之后插一个 1 pt 的普通空格（单独一个 run，约 0.25 pt 宽）作断点，断点前后各至少留 2 个字符；字母串与数字内部不断（与 HTML 不同：WPS 里从字母中间断开太扎眼，左对齐下行尾空出一小段可以接受）。紧跟数字、前面不是数字的 `-`（负号、指数）换成不断行连字符 U+2011：WPS 会在 `-` 后断行（`pct=-` | `1.431863`），`<w:noBreakHyphen/>` 在 WPS 里后面又多出约 1.7 pt；U+2011 在 Times New Roman 里与 `-` 同形同宽。数字之间的 `-`（区间、日期）不动。表格单元格两样都不做（用户拍板：表里的标识符与数值复制出去要能原样用，粘进 Excel 仍是数字），表题照正文处理。表格列宽按三档分配：每列先给 4 个字；还有余量就补到「不折坏」的宽度（最长不可断片段封顶 12 字、正文不超过 8 字、表头不超过 6 字）；再有余量补到自然宽度；分不满的那一档按各列差额的比例分。正文是长文本且一行放不下的列左对齐，其余列居中。段落、列表项、引用里最长的不可断西文片段达到 6（`displayWidth` 口径，约 11 个西文字符）时，这一段左对齐（`raggedRight`），插了断点的段落都在其中：1 pt 的断点空格在两端对齐时会和字缝一起被拉宽（实测 `rolling_ domination` 中间裂开近 6 pt），断开后仍剩下的长数字挪行也会把上一行摊开；左对齐的代价是右边缘不齐，有了断点，行尾空出的最多是一小段的宽度。行内公式不计入（`displayWidth` 按源码长度折算公式，带上下标的短公式也会超过阈值），显式指定了对齐方式的段落不受影响。阈值按字符数算、不分中英文，纯英文段落里 11 个字母以上的单词同样会让该段左对齐（写作提示词只产出中文论文）。

## 不做什么

- 不改页面结构：导出菜单只换四个选项（「导出 Word (.docx) / 导出 PDF / 导出 LaTeX (.zip) / 导出 HTML」）及其行为；
- 不引入第三方公式转换库（`mathml2omml` 是 LGPL-3.0），不接第三方渲染 / 转换 API；
- 不在服务端生成 Word：浏览器里就能生成，正文也不必上传；
- 不移除 `source_tex` 路线，不在本案落论文正文持久化（ADR-0012 阶段 B 另案）。

## 后果

- 正向：修一处，四种格式同时受益；Word 公式可编辑；PDF 不弹打印框、与编辑器所见一致；LaTeX 工程解压即可编译。
- 代价：服务端多一个浏览器依赖（缺失时诚实降级为浏览器打印；Linux 服务器另需中文字体）；HTML 源比 `.tex` 大得多；HTML / PDF 的断点用零宽空格，从 PDF 里复制长标识符会带上不可见字符；Word 正文的断点是普通空格、负号是 U+2011，从正文复制出的标识符在断点处多一个空格，负数粘进 Excel 等处不再被当成数字（表格单元格不受影响）。
- 已知局限：Word / WPS 里长数字（`0.0021355180250620664`）断不开，只能整段挪到下一行；含长串的段落左对齐，右边缘不齐，长数字前一行最多空出这个数的宽度。长串写在行内公式里（如 `\Delta R=-34.6550493072583\%`）时不计入，所在行仍可能被轻微拉开；表格单元格不插断点，比格子还宽的长串只能在格边硬断，窄格里的负数也可能在 `-` 后拆行。根本办法是论文正文少写原始指标名。

## 验收记录（2026-10-07，长串断点）

- 用户反馈左对齐后「一行一个等式、右边全空」（截图为同一篇第 25 页「再次，多目标选解……」段与 6.4 节），还有 `renew_util_storage_gain_pct=-` / `1.431863` 拆在两行。方法同上一节（6 篇、简化规则、WPS 用 COM 转 PDF、pypdfium2 量字形），另加两个量：段落中间行（下一行不是新段首行）的行尾留白，断点处的字距。
- 断点写法：零宽空格放进 1 pt 的 run，WPS 照样不断行（截图那篇 431 行，不插断点是 430 行）；1 pt 的普通空格生效。全部两端对齐 + 1 pt 空格：断点被拉开（截图那篇字距 ≥1 pt 的断点 102 处、≥3 pt 的 20 处），长数字前一行仍有 6 行字缝 ≥6 pt，所以含长串的段落保留左对齐。
- 行尾留白 ≥3 / ≥6 / ≥12 个字的行，改前→改后：截图那篇 57 / 38 / 8 → 25 / 3 / 1，合计留白 648 → 335 个字；b8ede1ff 24 / 19 / 8 → 7 / 2 / 1；e898f587 24 / 9 / 0 → 12 / 4 / 1。改后 ≥12 字的都是摘要末行（下接关键词，量具当成段中行）。字缝与上一节相同，只剩公式自带的间距；断点处字距中位数约 0.1 pt。
