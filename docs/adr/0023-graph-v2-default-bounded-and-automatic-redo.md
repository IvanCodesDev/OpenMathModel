# ADR-0023：Graph v2 成为缺省调度档位——回退有界、G3 推荐重做实验时先自动回实验、闸门预告回退余额

- 状态：Accepted（已落地：`agents/core` 的 `modeling_v2()` 图、`GraphScheduler` 的迭代 / 条件边裁定与 `iteration_budget`，引擎接线，`backend/api` 投影；`OMM_GRAPH` 缺省 `modeling-v2`）
- 日期：2026-09-18
- 关联：ADR-0011（编排选型：显式状态机与有界循环）、ADR-0013（终态可返工）、ADR-0019（任意状态从阶段重做）、设计文档 §6「Graph 工程」（§6.1 三步走、§6.4 迭代边、§6.5 影子等价）、附录 D2.1（E430→G3）

## 背景

ADR-0011 决定「运行拓扑唯一由 `agents/core` 状态机定义，不引入通用图编排」。此后的 Graph 工程没有推翻它，而是把同一个状态机写成**静态声明的图**（`GraphSpec`：节点 = 六个工作态，顺序边 = `WORK_SEQUENCE`，门 = G1–G4 声明），调度器只是这张图的读法：Graph v1（`linear-v1`）与原线性推进在 12 个控制流剧本、全部核心快照、worker / API 全链上逐一同答，2026-09-06 切为缺省；线性调度器留作影子，分歧只进日志。

在此之前，「退回重做」是**无界**的：G3 的「重做实验」、G4 的「退回修改」、跑完后的修订轮、对话面的「从某阶段重做」都是引擎按事件把状态搬回去，图对此一无所知，唯一的上限是控制面的 3 轮修订配额（只管修订这一个入口）。另一方面，验证不过时系统明明已经算出「推荐重做实验」，却仍要停下来等人点一次同样的选择。

Graph v2 在 v1 的节点与顺序边上只加两类**回环边**（前进路径逐字不变）：

- 迭代边（`iter`）：每个节点到自身及全部上游各一条，`max_iters = 3`（与修订轮数上限同口径）。任何回退入口都先问图：没有这条边 → E410；目标阶段已成功通过的次数 − 1 ≥ 上限 → E430。放行的许可（哪条边 / 第几轮 / 上限）记进触发回退的事件。
- 条件边（`cond`）：`validating → experimenting`，条件 `review.gate == 'G3' and review.impact.recommended == 'redo:EXPERIMENTING'`，`max_iters = 2`。检验节点要开 G3 且系统自己推荐重做实验时，图先替人回实验，最多两轮；轮次用尽（E430）才把 G3 交给人，卡片带 `iteration` 说明「图已替你重做过几轮」。

这两类边自 2026-09-08 起作为可选档位 `modeling-v2` 存在并有测试锚定；缺省仍是 `linear-v1`，等两件事：等价证据齐、闸门上能看见余额。

## 决策

### 1. `OMM_GRAPH` 缺省改为 `modeling-v2`

`DEFAULT_GRAPH_MODE = "modeling-v2"`，API 与 worker 两个装配点同步（都读同一个常量）。`linear-v1` / `shadow` / `off` 仍是合法档位，可显式选回无上限、无自动回退的旧口径；非法值按缺省处理并留警告，不静默换档。

切换依据（全部有测试）：evals 12 个控制流剧本 `modeling-v2` vs `off` 逐一相等（条件不成立时零差异）；条件边剧本在 core / evals / API 装配点各一条端到端（自动回实验两轮 → E430 → G3 → 人接受 → 完成，线性影子零分歧、回放一致）；整套 API 用例在 `modeling-v2` 下全绿——唯一需要改动的用例是「G3 人工选重做实验」，它验证的是人工回退语义，改为显式钉 `linear-v1`。

### 2. 回退余额随闸门下发，人在点之前就看见哪条路已走完

人工回退入口撞 E430 的处置取最薄口径：**不新增闸门类型、不改「修订提出时即裁」的语义**，而是让闸门自己说清。

- 调度器 `GraphScheduler.iteration_budget(snapshot, source_state)`：从提门阶段（节点自提闸门）或末节点（修订门）出发，图上每条迭代边此刻的余额——放行项 `{via_edge, iteration, max_iters, remaining}`，用尽项 `{via_edge, code: "E430", max_iters, taken}`；只列图上有边的目标；v1 图给空。纯函数。
- 引擎在 `REVIEW_REQUESTED` 与 `REVISION_REQUESTED` 的 payload 上带 `iteration_budget`（预算非空才带；v1 图键不出现，金轨迹 payload 逐字不变）。
- API 投影把预算落到「从某阶段重做」选项（`redo:<STATE>`）上：用尽的项**去掉推荐**（CTA 不再预选一个点了必 409 的项）并在说明里写「「X」已重做 N 轮，达图上限 M 轮，图不再放行此项」；有余额的项写「重做第 N/M 轮」，最后一轮点破。契约与前端零改动（选项 `description` 前端已渲染）。`resolve_review` 仍按同一裁定把关，撞上仍是 409 `GRAPH_ITERATION_REFUSED`——预告是便利，不是许可。

### 3. 自动回退在时间线上不冒充「用户要求」

条件边的自动回退与人工重做共用 `RUN_REDO` 事件，投影必须分得开：自动 → 状态行「「结果验证」未达标，图按条件边自动从「实验运行」重做（第 N/M 轮）」、节点行「图自动回退重做（第 N/M 轮）」、被作废的审批记 `superseded_by.kind = "auto_redo"`；人工 → 「用户要求从「X」重做（第 N/M 轮）」（v1 事件没有许可字段，括号不出现、文案与从前逐字相同）。轮次用尽才开的 G3 之前，时间线多一行 `run_log{kind: "auto_redo_exhausted"}`：「图已按条件边从「结果验证」自动回退「实验运行」重做 2 轮（上限 2 轮），结果仍未达标，交由你在闸门决定」；审批 `evidence` 留 `iteration` 与 `iteration_budget` 供审计。

### 4. 与 ADR-0011 的关系

ADR-0011 的三条承重不变量原样成立：金轨迹回归（v1 图 payload 逐字不变；v2 只在闸门多一键，控制流序列相同）、单投影驱动双栏（投影层只改文案与选项说明）、回放等于快照（每条新路径都有 `replay(events) == snapshot` 断言）。它拒绝的是**运行时可改拓扑的通用图引擎**；这里的图是装配期声明、装配期校验（E410 / E420）的静态拓扑，回环边给原本无界的回退**加上了**上限，与「循环分层有界」同向。ADR-0011 的「不引入通用图编排」继续有效，其「不自研 DAG 引擎」一句按本 ADR 读作「不自研运行时动态拓扑的图引擎」。

### 5. 明确不做（本阶段）

- 向前条件分叉、lane / join / seq 串行化：仍是【设计】，装配期拒绝（E410）。
- 人工回退撞 E430 时自动开一道新闸门让人「强制再来一轮」：不做——上限的意义就是三轮不成该由人换路（回到更上游的阶段是另一条边，各自计数）。
- 结果页展示跨轮对比、审批卡内嵌反馈包正文：随前端下一批。

## 结果

- 每一次回退都有界、有出处：事件上能数出第几轮，闸门上能看见余额，用尽的选项不再被预选。
- 验证明显不过（失败检查过半 / 实验审稿僵持）时系统先自己重做至多两轮，人只在图也没办法时才被打断；两轮之间实验节点拿到上一轮反馈包（ADR 外的 s34–s37 事实），不是原样重跑。
- 代价：缺省档下一次验证不过可能多花两轮实验 + 检验的模型与沙箱费用（受运行级预算硬停约束）；需要旧行为的部署显式设 `OMM_GRAPH=linear-v1`。
- 验证基线（2026-09-18，本机主树）：agents 六包 + worker 777 passed / 1 skipped，backend/api 464 passed / 2 skipped，共 1241 项全绿；ruff / mypy 无新增告警。
