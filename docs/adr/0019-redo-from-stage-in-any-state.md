# ADR-0019：任意状态下从选定阶段重做，判定以模型为主、规则为快路径

- 状态：Accepted（§4 步骤 2「短句规则直判、不出网」与步骤 4「模型 none 回落规则结果」已由 ADR-0020 修订——词表只作参考信号交给判定模型，不再单独触发）
- 日期：2026-09-06
- 关联：ADR-0013（终态可返工）、ADR-0018（对话即控制面；本 ADR 修订其 §1 判定分级与 §2 / §5 的「不改状态矩阵、失败运行不能选起点」）、ADR-0020（回复后执行、词表不再单独触发）、[前后端与 Agent 对接日志 §5.9](../development/frontend-backend-agent-integration.md)

## 背景

ADR-0018 落地后用户实测追问了三点，每一点都指向当时刻意保守的设计：

1. **「你现在只是通过固定的关键词来识别判断吗？」** 是。判定虽是两级，但弱模型那一级被三道门槛拦着：文本 ≤200 字、必须含与当前合法动作相关的「气味词」、不能是问句形态。没有气味词的句子根本不出网，体感就是只认关键词；判定模型也只看到这一句话与运行状态，看不到前几轮对话，「就按你刚说的那个做」解析不了。
2. **「我希望不管说什么，只要是需要执行的，都会出现真正的修改。」** 可执行的动作被状态机合法集锁死：FAILED 只能重试当前失败阶段；RUNNING / PAUSED / WAITING_APPROVAL 下的修改要求（「把模型换成随机森林重新做」）只被静默落成备注、影响后续节点——没有任何可见变化，正是用户说的「没有真正的修改」。
3. **「这个修改显示的进度，也不一定要接着上一次的显示。」** 即允许回退到更早的阶段重做，不必从当前阶段往后接。ADR-0018 §2 把「失败运行从更早阶段重做」推到后续一刀、§5 明文「不在 RUNNING 时按对话文本回退阶段，不改引擎状态矩阵」——这两条现在被推翻。

用户对三个问题的拍板：**规则只做第一层快路径，规则判不出的一律送模型判定**；**同一运行从选定阶段重做**（上游成果保留、进度接在原时间线上，而不是另起一次运行）；**重做先发提案、确认后执行**（与取消同级，因为会重新花费一遍）。

## 决策

### 1. 引擎：新增 `RUN_REDO` 事件，任意非完成状态都能回退到选定阶段

`agents/core` 新增领域事件 `RUN_REDO{target_state, from_state, reason, note_id?}`，由 `TaskRunEngine.redo(snapshot, target_state, reason, note_id)` 发出：

- **合法源状态**：任意工作态（执行中或已暂停）、FAILED、NEEDS_REVIEW。CREATED 没有可重做的东西，COMPLETED 继续走 ADR-0013 的修订门（门本身就是那道确认）。目标必须是工作态。
- **reducer**（`_on_run_redo`）：把仍在 RUNNING 的步骤按 CANCELLED 关掉（`error = "superseded: redo from <target>"`），清掉 `review` / `failure` / `paused` / `cancel_requested`，`state = target`，置 `force_rerun`，并像修订重做一样 `_discard_from(target)` 丢弃目标阶段及其下游的旧产出与闸门决策。上游各段不动。
- **状态矩阵不放宽**：`can_transition` 仍是前向矩阵，`STATE_CHANGED` 的校验不变；回退只能经这条显式事件发生，reducer 自行校验源 / 目标。这样调度器的 bug 不会借「工作态可以互跳」漏过去。
- 历史逐趟留档：被取代的步骤以 CANCELLED 留在 `steps`，重做后的步骤是 attempt+1；`revision_round` 不变（它记的是已完成运行上发起过几轮修订，与此无关）。

### 2. 控制面投影与在途节点让位

`engine_glue.redo_run(session, run, target, text)`（HTTP 与对话共用）：落 global 备注 → `engine.redo` → `RUN_REDO` 的投影把待审批门置为 CANCELLED（契约的 `resolution` 只表达「选了哪个选项」，作废的门与取消路径一样留空；作废原因记在内部 `evidence.superseded_by`）、RUNNING 步骤行置为 CANCELLED、清 `failure_*` / `paused_from_status` / `ended_at`、`current_node` 摆回目标阶段、状态置 RUNNING（「用户要求从「X」重做」）。下一 tick 推进器从目标阶段起跑。

**在途节点如何让位**：推进器 tick 是 checkpoint 模式——逐事件提交、节点执行期间不持写锁。控制路径在节点执行中追加了 `RUN_REDO` 之后，那个节点收尾写 `(run_id, seq)` 必然撞唯一约束。这不是新问题（今天暂停 / 取消撞上在途节点走的就是这条路，只是日志是一段堆栈），本 ADR 把它明确成契约：`WorkflowAdvancer.advance` 识别「seq 唯一约束冲突 / 事务已回滚」→ 记一行 warning「在途步骤已被控制动作取代，丢弃结果」，不再当异常。代价如实说明：**推进是单线程，在途节点的当前调用跑完之前，重做的第一步不会开始**（协作式中断留待后续），用户在提案文案里会看到这一点。

### 3. 对话：`redo` 动作，先提案后确认

`run_control` 的动作枚举加 `redo`（携带 `stage`）：

| 运行状态 | 合法动作 | 说明 |
|---|---|---|
| FAILED | `retry`（直接）/ `redo`（提案） | 「继续」「再试一次」= 重试当前失败阶段；点名了更早的阶段、或判定模型认为要改的内容属于更早阶段 = 从那一阶段重做 |
| RUNNING / PAUSED | `pause` / `resume` / `cancel`（提案）/ `redo`（提案） | 「把目标函数改成加权成本」此前只是静默备注；现在判定模型会判断它属于哪个阶段：属于已完成或正在执行的阶段 → 提案从该阶段重做；属于尚未开始的阶段 → 仍落备注（该阶段执行时会读到） |
| WAITING_APPROVAL（节点自提的闸门） | `approve` / `reject` / `cancel`（提案）/ `redo`（提案） | 门上已有对应选项（G1 的「退回重做方案」）时优先选项；要回到门更早的阶段才用 `redo`，执行时该门作废 |
| WAITING_APPROVAL（修订门） | `approve` / `cancel` | 六个起点已经在门上，直接选项，不另开 `redo` |
| COMPLETED | `revision` | 不变（ADR-0013 / ADR-0018） |

提案形态沿用 ADR-0018 的 `action{status:"proposed"}`：提案里带 `stage` / `stage_label` / 用户原话；下一轮「确认」或点按钮时按提案里的阶段执行，原话落成 global 备注让重做的节点读到「要改什么」。「不 / 算了」作废。

### 4. 判定：模型为主、规则为快路径，带最近几轮对话

`decide` 的顺序改为：

1. 上一轮留有待确认提案 → 只看确认 / 否定词（不出网）；
2. 本地规则命中且消息是**短句**（规范化后 ≤12 字：「继续啊」「再试一次」「用方案 B」「从数据准备重做」）→ 直接采用，不出网；
3. 其余一律送判定模型（有配置的接口且文本 ≤800 字）；判定器除运行状态、失败原因、待审批选项、合法动作外，还拿到**最近三轮对话**（用户原话与助手回复的摘要）以及阶段顺序和当前所在阶段，输出 `{action, option_id, stage}`；
4. 模型判成 `none`、判定异常、结果不在合法集内 → 回落到本地规则的结果（可能仍是某个动作，也可能是 none）。

删掉的门槛：气味词（`has_command_hint`）、问句形态短路、200 字上限。保留的红线：结果必须在合法集内；`redo` 必须带合法阶段（模型没给时按正文关键词 `suggest_revision_stage` 推断）；不可逆 / 要花钱的动作（取消、重做）先提案。判定模型仍取接口池里最弱的一个，用量按 `route` 口径记账——现在每条任务页消息（短句除外）都会多这一次调用，这是用户明确接受的代价。

### 5. 明确不做

- 不另起新运行、不新建进度条：用户选了「同一运行接着显示」。
- 不做协作式中断：在途节点跑完当前调用后才让位，其结果被丢弃。
- 不给对话模型开放工具调用；动作仍由确定性合法集兜底（ADR-0018 §5 第一条不变）。
- 首页对话（`chat_…` 归属）不经过控制步骤（不变）。

## 结果

- 任意非完成状态下，一句「换成随机森林重新做」都会变成一张可确认的重做提案，确认后运行真的回到建模方案阶段重跑，时间线上该阶段出现新的一趟尝试，上游成果保留。
- 判定不再取决于用户是否碰巧说出词表里的词；规则只负责把最常见的短命令免出网。
- 代价：每条非短句消息多一次弱模型判定；重做会重新消耗目标阶段及其下游的运行配额（所以要确认）；在途节点让位有延迟。
- ADR-0018 §2「失败运行不能选起点重做」、§5「不在 RUNNING 时按对话文本回退阶段 / 不改引擎状态矩阵」由本 ADR 修订。
