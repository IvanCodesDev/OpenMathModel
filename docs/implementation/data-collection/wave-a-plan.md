# Wave A：官方赛题数据采集执行计划

## 目标与边界

本阶段按《全流程开发规划》第 10 节与 Phase 7 执行：覆盖 COMAP、APMCM、全国大学生数学建模竞赛、中国研究生数学建模竞赛和 1 个用户指定社区仓库，建立可重复、可增量、可追踪的数据管道。进入前端赛题库的记录必须具有完整题面，不允许以摘要模板或外链替代正文。

首批来源：

1. COMAP MCM/ICM 往届赛题页；
2. 中国研究生数学建模竞赛入口；
3. APMCM 竞赛题目入口。
4. `zhanwen/MathModel` 固定 commit 社区快照（完整题面补充来源）。
5. 全国大学生数学建模竞赛官网 2021–2025 年年度赛题包。

所有来源在进入产品前维持 `pending_human_confirmation`，由人工确认“官方/官方合作方/转载站”并补齐权利复核记录。

## 数据量爬坡

数量是通过质量门禁后的规模目标，不以牺牲来源与附件一致性换取：

- **Seed（当前）**：5 个注册来源，前端仅发布 86 道完整题面，验证端到端链路。
- **Wave A1**：3 个来源 × 5 年，目标形成约 75–120 条题目记录及其附件关系。
- **Wave A2**：完成上述题目可公开附件的内容寻址快照、解析版本与 QA 记录。
- **Wave B**：扩展到 8–12 个赛事和历史年份，目标 1,000+ 条题目/政策/结果元数据；全文只保存许可允许的内容。
- **Wave C**：关联方法卡、指标、风险、文献和可执行 Recipe；每条知识边保留证据、抽取版本、置信度和审核状态。

## 批次策略

1. 每个来源独立批次，失败不阻塞其他来源；慢站缩小 `--max-pages` 后重跑。
2. 单来源并发固定为 1，按 Registry 的每分钟请求数限速，429/5xx 指数退避。
3. 先跑 metadata 模式；只有 A2 人工门禁通过的来源才启用 `--include-attachments`。
4. 原始对象按 SHA-256 内容寻址；运行 Manifest 不覆盖；解析器升级生成新版本。
5. 每批运行 `tools/verify-data-collection.ps1 -RequireRuntimeData`，保存字节数、唯一内容数、链接数、错误数和退出码。
